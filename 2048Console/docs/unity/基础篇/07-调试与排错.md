# 07　调试与排错（比写代码更重要）

写游戏 80% 的时间花在"为什么它不按我想的动"。这一章讲清楚出问题时该看什么、怎么定位。

## 7.1 Console 窗口：第一现场

Console 会显示三类信息，颜色不同：

| 类型 | 颜色 | 含义 |
| --- | --- | --- |
| `Debug.Log` | 白/灰 | 普通日志 |
| Warning（警告） | 黄 | 不致命，但通常是"你这样写可能有问题" |
| **Error（错误）** | **红** | 有问题。**编译错误会阻止进入 Play 模式** |

几个必须知道的开关（Console 右上角）：

| 开关 | 作用 |
| --- | --- |
| `Clear` | 清空；更重要的是它旁边的 **Clear on Play**（进 Play 时自动清空）——建议打开 |
| `Error Pause` | 出错时自动暂停游戏。**强烈建议打开**：能在出错那一刻看到现场 |
| `Collapse` | 把相同日志折叠成一条带计数的。日志刷屏时救命 |
| 点击一条日志 | 下面会展开调用栈；**栈里点一下会跳到对应代码行** |

## 7.2 Debug.Log 家族

```csharp
Debug.Log("普通信息");
Debug.LogWarning("警告：可能有问题");
Debug.LogError("错误：这次肯定不对");

// 带格式化，比字符串拼接清楚
Debug.Log($"位置 = {transform.position}, 分数 = {score}");

// 第二个参数是"上下文对象"：点日志时会高亮场景里对应的对象
Debug.Log("撞到东西了", gameObject);
```

**什么时候用**：验证"这段代码到底有没有执行""这个值到底是多少"。

**什么时候别用**：

- **不要写在 `Update` 里**（每秒 60 条，Console 直接爆掉）。真要每帧看，用 `Time.frameCount % 60 == 0` 每 60 帧打一次，或者干脆用断点
- 不要用 `Debug.Log` 替代断点。**能打断点的地方就打点**，看到的是完整现场，不是一个值

## 7.3 怎么读一条报错

典型的一条：

```
NullReferenceException: Object reference not set to an instance of an object
PlayerController.Update () (at Assets/Scripts/PlayerController.cs:42)
```

拆开看：

| 部分 | 含义 |
| --- | --- |
| `NullReferenceException` | 异常类型：**你访问了一个 `null` 的东西**（调方法、读字段） |
| `PlayerController.Update ()` | 出错的函数：`PlayerController` 里的 `Update` |
| `(at Assets/Scripts/PlayerController.cs:42)` | **精确到文件和行号**——直接去第 42 行 |

**最常见的五种报错**：

| 报错 | 九成原因 | 怎么修 |
| --- | --- | --- |
| `NullReferenceException` | Inspector 里某个引用字段是 `None` | 找到那一行，看它用了哪个字段，回 Inspector 拖上 |
| `MissingReferenceException` | 引用的对象已经被 `Destroy` 了 | 检查销毁时序，或者在用之前判 `if (obj == null) return;` |
| `UnassignedReferenceException` | 同上，字段没赋值 | 拖引用 |
| `IndexOutOfRangeException` | 数组/列表下标越界 | 检查循环边界和坐标换算 |
| `The script class cannot be found` / 挂不上脚本 | 文件名和类名不一致 | 改成一致（且不能有空格） |

## 7.4 断点调试（Rider + Unity，最有效的手段）

比 `Debug.Log` 强十倍，因为你能看到**所有**变量的值、调用栈、以及每一步的变化。

**操作流程**：

1. Rider 右上角运行配置选 `Attach to Unity Editor`
2. **先在 Unity 里点 ▶ 进 Play**（顺序不能反）
3. 再点 Rider 的 🐞（Debug）→ `Attach to Unity Editor & Play`
4. 在代码行号左边点一下打红点（断点）
5. 代码执行到那一行时整个游戏会冻住，此时：

| 操作 | 快捷键 | 作用 |
| --- | --- | --- |
| 单步跳过 | `F8` | 执行这一行，不进函数内部 |
| 单步进入 | `F7` | 进入这行调用的函数 |
| 继续 | `F5` | 跑到下一个断点 |
| 看变量 | 鼠标悬停 / Variables 面板 | 看当前所有局部变量和字段 |
| 看调用栈 | Frames 面板 | 谁调用了这个函数（**追"这个值是谁改的"特别有用**） |

**三个实用技巧**：

- **条件断点**：右键断点 → 设条件（比如 `x == 3`），只在满足条件时停下。循环里调试必用
- **日志断点**：右键断点 → 不暂停，只打印一条消息。相当于"不用改代码的 Debug.Log"
- **调试完记得断开**：Attach 状态下 Unity 会明显变慢，改完记得停掉调试会话

## 7.5 运行时看数据：把私有字段暴露出来

最快的检查手段其实是 **Inspector 实时值**：

```csharp
[SerializeField] private int _score;        // 运行时在 Inspector 里能看着它变
[SerializeField] private bool _isBusy;
```

进 Play 后选中对象，Inspector 会实时刷新这些值。**"分数为什么不变"这类问题，看一眼就知道是没算还是没显示。**

## 7.6 可视化调试：在场景里画线

计算类逻辑（坐标、方向、范围）用日志很难看出问题，画出来最快：

```csharp
// 在 Scene 视图里画辅助图形，只在编辑器里显示，不影响发布
private void OnDrawGizmos()
{
    Gizmos.color = Color.red;
    Gizmos.DrawWireSphere(transform.position, 1.5f);       // 画个圈看看范围对不对

    Gizmos.color = Color.green;
    Gizmos.DrawLine(transform.position, transform.position + Vector3.right * 3f);
}

// 也可以在 Game 视图里画线（只在运行时可见）
void Update()
{
    Debug.DrawLine(transform.position, target.position, Color.yellow);
}
```

`OnDrawGizmos` 是 MonoBehaviour 的回调，**不需要进 Play 就会画**（改参数立刻能看到），做布局类工作非常方便。

## 7.7 暂停与逐帧

时序类的 bug（动画抖动、连按出问题）靠"暂停 + 逐帧"最容易定位：

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+P` | 开始/停止 |
| `Ctrl+Shift+P` | 暂停 |
| `Ctrl+Alt+P` | 暂停状态下**单步一帧** |

暂停时改 Inspector 里的值也生效，可以一边逐帧一边调参数。

## 7.8 "引用空了"的排查流程

这是新手最常卡的一类问题，按顺序查：

1. **Console 有没有红色报错**？没有报错说明代码在跑，问题在表现
2. 报错指向哪一行？那一行用了哪个字段？→ **去 Inspector 看那个字段是不是 `None`**
3. 字段在 **Prefab** 上吗？场景实例上设的引用如果没 `Apply`，`Instantiate` 出来的新对象还是空的
4. 对象是不是被 `SetActive(false)` 了？禁用的对象不执行 `Awake`/`Start`，字段可能还没初始化
5. 代码是不是访问"还没生成"的对象？`Instantiate` 之前就 `GetComponent` 会拿到 `null`
6. 实在找不到：在用它之前加一行 `if (x == null) { Debug.LogError("x 是空的"); return; }`，把范围缩到最小

## 7.9 怎么查文档和搜问题

**官方 Scripting API**（最权威）：搜 `Unity Scripting API 类名`，比如 `Unity Scripting API Transform`。看某个方法时注意看**它属于哪个组件**。

几个搜索技巧：

| 情况 | 怎么搜 |
| --- | --- |
| 报错 | **把报错原文（英文）整句粘进搜索框**，别翻译 |
| 想实现某功能 | 搜"unity + 功能英文名 + tutorial"（英文资料多十倍） |
| API 用法 | 优先看官方文档的代码示例，其次看 Unity Discussions（原 Unity Answers/Forum） |
| 版本相关 | 加上版本号，比如 `unity 2022.3 Input System`；网上大多数答案基于 2021/2022 LTS，基本都能直接用 |

**遇到不认识的报错别慌**：Unity 的报错信息普遍比 .NET 的直白，`NullReferenceException` 几乎都是"引用没拖"。

## 7.10 本章动手

1. 在 Console 右上角打开 `Clear on Play` 和 `Error Pause`
2. 故意写一段会 `NullReferenceException` 的代码（比如 `[SerializeField] private Transform target;` 然后在 `Update` 里 `target.position`），运行看报错，**点开调用栈跳到那一行**
3. 用断点方式重现同一个问题：在出错行前一行打断点，Attach 后看 `target` 是不是 `null`
4. 写一个 `OnDrawGizmos` 画出以自己为圆心、半径 2 的圆，然后在 Scene 视图里改 `transform.position` 观察
5. 把 Console 的 `Collapse` 打开，写一段每帧打日志的代码，看它如何把 1000 条折叠成 1 条
