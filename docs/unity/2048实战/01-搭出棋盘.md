# 01　搭出 4×4 棋盘

这一章结束时，Game 视图里会有一个由代码生成的 4×4 棋盘。

## 1.1 先设计结构（这一步别跳过）

控制台版里只有两样东西：`s_map`（数据）和 `ShowMap`（画）。Unity 里对象是真实存在的，所以先把"场景里有哪些对象"定下来：

```
SampleScene
├── Main Camera            （Size = 4）
├── Board                  ← 空对象，挂 BoardView，棋盘的父亲
│   ├── Tile_0_0           ← 运行时由 Instantiate 生成（不是手工摆的）
│   ├── Tile_1_0
│   ├── ...
├── Canvas                 ← UI（2048 实战 03做分数和按钮）
```

**为什么棋盘要有父亲 `Board`**：以后想整体平移/缩放棋盘，只改 `Board` 一个对象的 Transform；想清空棋盘，遍历子对象逐个销毁即可。

**为什么每格用一个对象**：将来要"让这一格滑到那边去"，那是**位置**的变化，而位置只有对象才有。

## 1.2 造一个"方块"：Tile Prefab

### 第 1 步：做样子

1. Hierarchy 右键 → `2D Object → Sprites → Square`，命名 `Tile`
2. Transform：Position `(0,0,0)`，Scale `(0.95, 0.95, 1)`
3. SpriteRenderer：Color 设为浅灰（后面代码会按数值改颜色）
4. 子对象：右键 `Tile` → `Create Empty`，命名 `Label`，Add Component → 搜 `TextMeshPro`（**不带 UGUI 的那个**，它吃世界坐标、跟着父对象走）
5. `Label` 设置：Text = `2`，Font Size = 6，Alignment 居中，Position `(0, 0, -0.1)`

> Z 的细节：让文字"贴在方块表面又不被挡住"，把文本的 Z 设得比方块略小最保险。看不到文字时先试 `-0.1` 或 `-1`。

### 第 2 步：写 TileView 脚本

在 `Assets` 下建文件夹 `Scripts`，新建 `TileView.cs`（**文件名必须和类名一致，不要有空格**）：

```csharp
using TMPro;
using UnityEngine;

/// <summary>
/// 一个方块的"表现层"：只负责根据数字改变自己的样子，不参与任何游戏规则。
/// </summary>
public class TileView : MonoBehaviour
{
    [SerializeField] private SpriteRenderer background;   // Inspector 里拖进来
    [SerializeField] private TextMeshPro label;            // Inspector 里拖进来

    // 不同数字对应的背景色（用数组，够用又省事）
    private static readonly Color[] Colors =
    {
        new Color32(0xEE, 0xE4, 0xDA, 0xFF),   // 0：空
        new Color32(0xEE, 0xE4, 0xDA, 0xFF),   // 2
        new Color32(0xED, 0xE0, 0xC8, 0xFF),   // 4
        new Color32(0xF2, 0xB1, 0x79, 0xFF),   // 8
        new Color32(0xF5, 0x95, 0x63, 0xFF),   // 16
        new Color32(0xF5, 0x7C, 0x5F, 0xFF),   // 32
        new Color32(0xF6, 0x5E, 0x3B, 0xFF),   // 64
        new Color32(0xF2, 0xD4, 0x4C, 0xFF),   // 128
        new Color32(0xF2, 0xD4, 0x4C, 0xFF),   // 256
        new Color32(0xF2, 0xD4, 0x4C, 0xFF),   // 512
        new Color32(0xED, 0xC2, 0x2E, 0xFF),   // 1024
        new Color32(0xED, 0xC2, 0x2E, 0xFF),   // 2048
    };

    /// <summary>显示一个数值。value == 0 表示这一格是空的。</summary>
    public void SetValue(int value)
    {
        if (value == 0)
        {
            label.text = string.Empty;
            return;
        }

        label.text = value.ToString();
        int index = Mathf.Clamp(Mathf.RoundToInt(Mathf.Log(value, 2)), 1, Colors.Length - 1);
        background.color = Colors[index];
    }
}
```

要点：

- `[SerializeField] private` —— 私有但在 Inspector 可见，Unity 里推荐的字段写法
- `Mathf.Log(value, 2)` 求"2 的几次方"，正好对应数值本身
- 这个脚本**只管长什么样**，不知道"能不能移动""该不该合并"

### 第 3 步：把 Tile 变成 Prefab

1. `Assets` 下建文件夹 `Prefabs`
2. 把 Hierarchy 里的 `Tile` 拖进 `Prefabs` → 生成 `Tile.prefab`
3. 选中 Hierarchy 里的 Tile，在 Inspector 里给两个引用赋值（`background` 拖自己的 SpriteRenderer，`label` 拖子对象 Label）
4. 点 Inspector 顶部的 **Apply**（或右键 Prefab → Apply All），把引用写回 Prefab 本体
5. 删掉场景里的 Tile 实例（后面用代码生成）

> **引用必须在 Prefab 上设好并 Apply**。最常见的坑：在场景实例上设了引用但没 Apply，`Instantiate` 出来的新方块两个引用都是 `None`，运行时报 `NullReferenceException`。

## 1.3 用代码生成棋盘

新建 `Scripts/BoardView.cs`：

```csharp
using UnityEngine;

/// <summary>
/// 棋盘的表现层：生成格子对象、把逻辑数据同步到画面上。
/// </summary>
public class BoardView : MonoBehaviour
{
    [SerializeField] private GameObject tilePrefab;   // 把 Tile.prefab 拖进来
    [SerializeField] private float spacing = 1.1f;    // 格子中心间距（世界单位）

    private const int Size = 4;
    private TileView[,] _tiles;                       // [x, y]

    /// <summary>格坐标 (0..3, 0..3) → 世界坐标，棋盘中心在原点。</summary>
    public Vector3 GridToWorld(int x, int y)
    {
        float offset = (Size - 1) * 0.5f;             // 1.5
        return new Vector3((x - offset) * spacing, (y - offset) * spacing, 0f);
    }

    void Awake()
    {
        CreateTiles();
    }

    private void CreateTiles()
    {
        _tiles = new TileView[Size, Size];

        for (int x = 0; x < Size; x++)
        {
            for (int y = 0; y < Size; y++)
            {
                GameObject go = Instantiate(tilePrefab, transform);   // 挂到 Board 下面
                go.name = $"Tile_{x}_{y}";
                go.transform.position = GridToWorld(x, y);

                _tiles[x, y] = go.GetComponent<TileView>();
                _tiles[x, y].SetValue(0);
            }
        }
    }

    /// <summary>把整张逻辑棋盘画出来。board[x, y] == 0 表示空格。</summary>
    public void Refresh(int[,] board)
    {
        for (int x = 0; x < Size; x++)
        {
            for (int y = 0; y < Size; y++)
            {
                _tiles[x, y].SetValue(board[x, y]);
            }
        }
    }
}
```

**坐标怎么算的**：格坐标 `0..3`，要让 4 个格子对称分布在原点两侧，`(x - 1.5)` 把 `0..3` 映射成 `-1.5, -0.5, 0.5, 1.5`，再乘间距 `1.1` 就是世界坐标。摄像机 Size = 4 时棋盘刚好占屏幕中间。

## 1.4 挂上去、测一测

1. Hierarchy → `Create Empty`，命名 `Board`
2. 给 `Board` 挂 `BoardView` 组件（Add Component → 搜 `BoardView`）
3. Inspector 里把 `Tile.prefab` 拖到 `tilePrefab` 字段
4. 点 ▶ 运行

**预期**：Game 视图出现 16 个灰色方块，排成 4×4；Hierarchy 里 `Board` 下面自动长出 `Tile_0_0` … `Tile_3_3`。

没看到的话依次检查：`tilePrefab` 是否为空（Console 会报 `NullReferenceException`）、摄像机 Size 和位置、Prefab 的 Scale 与方块图的尺寸是否匹配（1 个世界单位大的图 + Scale 0.95 = 差不多满格，间距 1.1 会留缝，正常）。

## 1.5 让它显示真实的数字（冒烟测试）

临时挂一个测试脚本，验证表现层：

```csharp
using UnityEngine;

public class BoardViewSmokeTest : MonoBehaviour
{
    private BoardView _view;

    void Awake()
    {
        _view = GetComponent<BoardView>();
    }

    void Start()
    {
        int[,] demo =
        {
            { 2,  0,  0,   4 },
            { 0,  0,  0,   0 },
            { 0, 16,  0,   0 },
            { 0,  0,  0, 128 },
        };
        _view.Refresh(demo);
    }
}
```

运行后应该看到：左上 2、右上 4、中间 16、右下 128，颜色各不相同（128 开始偏黄）。验证完删掉或禁用这个脚本。

## 1.6 对照你的 2048

| 控制台版 | Unity 版 |
| --- | --- |
| `s_map = [[0,0,0,0], ...]` 手写初始化 | `new int[Size, Size]`（Unity 里习惯用 `int[,]`） |
| 屏幕就是"4 行文本" | 16 个真实对象排在 `Board` 底下 |
| `ShowMap()` 每次重写 4 行文本 | `Refresh(board)` 把数据刷到 16 个 `TileView` |
| 一个格子 = 一个字符位置 | 一个格子 = `_tiles[x, y]` 这个对象 |

**这一章刻意没做逻辑**：`Refresh` 只负责"把数据画出来"。这样2048 实战 02搬算法时，你能清楚看到"改动只发生在逻辑层，表现层一行都不用动"。
