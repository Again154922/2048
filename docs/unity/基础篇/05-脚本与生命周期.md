# 05　脚本与生命周期：时间与协程

这一章要解决两件事：**搞清楚 Unity 什么时候调用你的代码**，以及**把你从"控制台思维"里拽出来**。

## 5.1 MonoBehaviour：你的类是被引擎"驱动"的

控制台程序的骨架是这样：

```csharp
static void Main()
{
    Init();
    while (running)      // ← 你写的循环
    {
        HandleKey();
        ShowMap();
    }
}
```

**Unity 里没有 Main，也没有你写的循环。** 引擎自己有一个永不停止的游戏循环，它做的是：

> 每一帧：更新所有对象的组件 → 渲染 → 读输入 → **调用挂在你脚本上的那几个"回调函数"**

你写的 `Update()` 就是"引擎每帧叫我一次"。一个场景里有 50 个脚本，就是每帧调用 50 次 `Update`。所以：

```csharp
void Update()
{
    if (Input.GetKeyDown(KeyCode.LeftArrow)) Move(Left);   // 这就是你的"游戏循环"
}
```

你 v2.0 里 `Main` 那个 `while` 循环，在 Unity 里**由引擎替你转**，你只提供"每一帧该做的事"。

## 5.2 生命周期函数一览（按调用顺序）

| 顺序 | 函数 | 什么时候调用 | 用途 |
| --- | --- | --- | --- |
| 1 | `Awake()` | 对象**被创建/场景加载**时，只一次 | 初始化自己的字段、`GetComponent` 缓存引用 |
| 2 | `OnEnable()` | 组件被启用时（每次激活都会） | 注册事件、订阅回调 |
| 3 | `Start()` | 第一次 `Update` **之前**，只一次 | 需要在别的对象也 `Awake` 完之后做的事 |
| 4 | `FixedUpdate()` | 固定间隔（默认 0.02s），和物理同步 | 物理相关（我们用不到） |
| 5 | **`Update()`** | **每帧一次**（帧率越高调用越多） | 输入、逻辑、计时 |
| 6 | `LateUpdate()` | 每帧 `Update` 全部跑完之后 | 摄像机跟随（要等对象先移动完） |
| 7 | `OnDisable()` | 组件被禁用/销毁时 | 反注册事件 |
| 8 | `OnDestroy()` | 对象被销毁时 | 释放资源 |
| — | `OnApplicationQuit()` | 应用退出前 | 你已经在 `Main Camera.cs` 里用过了 ✓ |

**`Awake` 还是 `Start`？** 简单记：

- 自己初始化自己 → `Awake`
- 需要用到**别的对象**（比如棋盘脚本要去找 `BoardView`）→ `Start`，因为那时所有对象的 `Awake` 都跑完了

**`Update` 还是 `LateUpdate`？** 只有当你的代码需要"在别人都动完之后再动"时才用 `LateUpdate`（典型是摄像机跟随）。2048 用不到。

## 5.3 ⚠️ 重点：不要再开后台线程轮询（看你自己的代码）

你在 `Stopwatch.cs` 里写了这个：

```csharp
void Start()
{
    Task.Run(() =>
    {
        while (true)
        {
            while (_getEvent)
            {
                GetKeyEvents();     // 这里面读 KeyStatus（来自 Input.GetKeyDown）
                Debug.Log("Getting Key Events");
                _getEvent = false;
            }
        }
    });
}

void Update()
{
    _getEvent = true;           // 主线程举手："喂，后台线程你可以干活了"
    ...
}
```

`Main Camera.cs` 里也是同一套路。这段代码的意图我猜是：**想让按键检测"独立于帧率"**，或者担心"Update 太快/太慢会漏按键"。但这个做法在 Unity 里有四个问题，一个比一个严重：

**① Unity 的 API 不能在后台线程调用。**
`Input.GetKeyDown`、`Debug.Log`、`transform.position`、`GetComponent`、`Instantiate`、`Random.Range`（Unity 的）、`Time.time`……这些**只能在主线程调用**。在后台线程里调用它们，Unity 会抛 `UnityException: ... can only be called from the main thread`，或者在某些情况下静默返回垃圾值。你的 `Task.Run` 里恰好就在调 `Debug.Log`。

**② `while(true)` 空转会吃满一个 CPU 核心。**
外层 `while(true)` 里如果没有 `_getEvent`，就一直在自旋（spin），什么也不干但 CPU 占用 100% 的一个核。这也是为什么很多 Unity 新手项目笔记本风扇狂转。

**③ 你在两处读写 `_getEvent`，没有内存屏障。**
主线程写 `_getEvent = true`，后台线程读 `while (_getEvent)`。编译器/CPU 都可能重排或缓存这个值，且 `bool` 不是 `volatile`。结果就是"有时候按键没反应，有时候莫名其妙触发了两次"——**典型的竞态 bug，症状随机、极难复现**。

**④ 最关键：完全没必要。**
`Update()` 本身就是每帧调用一次的循环。输入是**事件化的**：`Input.GetKeyDown` 在"这一帧内按下"时为 true，你每帧查一次就不会漏（Unity 的输入在帧之间会被缓存，一帧内多次按键会按顺序被读到）。你不需要任何额外的循环。

### 正确的写法

秒表这个需求（空格暂停/继续、R 归零）在 Unity 里是这样：

```csharp
using TMPro;
using UnityEngine;

public class Stopwatch : MonoBehaviour
{
    [SerializeField] private TextMeshPro timerText;   // Inspector 里拖进来，不要用 GetComponent 硬找

    private float _elapsed;      // 已经走过的时间（秒）
    private bool _isRunning;

    void Update()
    {
        // 1) 先处理输入 —— 每帧查一次，不会漏
        if (Input.GetKeyDown(KeyCode.Space))
        {
            _isRunning = !_isRunning;
        }

        if (Input.GetKeyDown(KeyCode.R))
        {
            _isRunning = false;
            _elapsed = 0f;
        }

        // 2) 再推进时间 —— 用 deltaTime，和帧率无关
        if (_isRunning)
        {
            _elapsed += Time.deltaTime;
        }

        // 3) 最后更新显示
        timerText.text = _elapsed.ToString("F1");
    }
}
```

代码从 ~105 行变成 ~30 行，线程没了，竞态没了，CPU 占用也正常了。**这是本教程最重要的一次重写，请确认你看懂每一条改动。**

## 5.4 时间：`Time.deltaTime` 和 `Time.time`

你在秒表里用 `DateTime.Now` 求毫秒差。用它能算出"真实流逝的墙钟时间"，但在游戏里几乎总是错的：

| 需求 | 该用 | 不该用 |
| --- | --- | --- |
| "经过了多少秒" | `Time.time`（游戏开始到现在的秒数） | `DateTime.Now` |
| "这一帧花了多久" | `Time.deltaTime`（上一帧到这一帧的秒数） | 手算时间戳 |
| "暂停/加速游戏" | `Time.timeScale = 0f`（暂停）或 `2f`（两倍速） | 基本做不到 |

**为什么 `deltaTime` 是关键**：机器性能不同，帧率也不同（60 帧/秒 vs 144 帧/秒）。`Update` 里写：

```csharp
// ❌ 每秒移动 60 米还是 144 米，取决于你的显卡
transform.position += new Vector3(1f, 0, 0);

// ✅ 不管帧率多少，都是每秒 5 米
transform.position += new Vector3(5f, 0, 0) * Time.deltaTime;
```

`Time.timeScale = 0` 时 `Time.deltaTime` 会变成 0，所以"暂停"只需要改一个数值——这也是为什么游戏应该用 `Time` 而不是墙钟。

**对 2048 来说**：棋盘移动是瞬时完成的（一按方向键，数据立刻算完），所以 `deltaTime` 主要用在**动画**上（2048 实战 03）。

## 5.5 协程：做"等一会儿"的事，不阻塞、不开线程

有些事需要"过一段时间再继续"：方块滑动的动画、延时 0.2 秒后再生成新方块、提示文字淡出。

新手常见的三个错误做法：

- `Thread.Sleep(500)` → **会冻结整个游戏**（主线程在睡）
- `Task.Run` + `await Task.Delay(500)` → 回到后台线程问题
- 在 `Update` 里手工维护计时器 + 一堆状态标志 → 状态爆炸（你现在的写法就是往这个方向走）

**正确做法：协程（Coroutine）**。它本质上是"可以让出执行权、下一帧再继续"的方法：

```csharp
void Start()
{
    StartCoroutine(DemoRoutine());
}

System.Collections.IEnumerator DemoRoutine()
{
    Debug.Log("开始");
    yield return null;                        // 让出：下一帧再往下走
    Debug.Log("过了一帧");
    yield return new WaitForSeconds(1.5f);    // 等 1.5 秒（受 timeScale 影响）
    Debug.Log("过了 1.5 秒");
}
```

要点：

- 返回类型必须是 `IEnumerator`，用 `yield return xxx` 分步
- 用 `StartCoroutine(...)` 启动；`StopCoroutine` / `StopAllCoroutines` 停止
- 触发它的那个 MonoBehaviour 被禁用或销毁时，协程自动停止（很好的特性）
- `yield return null` = 等下一帧；`WaitForSeconds` = 等 N 秒；`WaitForSecondsRealtime` = 不受 `timeScale` 影响的 N 秒

**2048 里协程用在哪**：按下方向键 → 数据算完 → 启动协程 → 方块用 0.1 秒滑到新位置 → 生成新方块。2048 实战 03会给出完整代码。

## 5.6 执行顺序的小陷阱

几个你现在就该知道的规则：

1. **场景中所有对象的 `Awake` 都会先跑完，才开始跑 `Start`**。所以 `Start` 里可以安全访问别的对象。
2. **同一个对象上的多个脚本，`Update` 的执行顺序是"不确定的"**（除非在 `Project Settings → Script Execution Order` 里手动排）。**不要依赖两个脚本的 Update 谁先谁后**——这是很多诡异 bug 的来源。需要顺序时，就用协程或者合成一个脚本。
3. **`Instantiate` 出来的对象，`Awake` 会立刻执行，`Start` 在下一帧前执行**。所以 `Instantiate` 完马上访问它的字段是可行的（`Awake` 已跑）。
4. **`Destroy(obj)` 是延迟到帧末真正销毁**，之后的同一个 `Update` 里它还在。要马上"看不见"就 `SetActive(false)`。

## 5.7 对照你的 2048：这边要怎么改

你 v2.0 的结构：

```csharp
static void Main() { Init(); while (s_gamerunning) { HandleKey(); CheckGameState(); ShowMap(); } }
```

翻译成 Unity 的几个脚本：

| 控制台里的东西 | Unity 里放哪 |
| --- | --- |
| `Init()`（读档、建棋盘） | `BoardController.Awake()` / `Start()` |
| `HandleKey()` 里的 `Console.ReadKey` | `BoardController.Update()` 里的 `Input.GetKeyDown` |
| `MoveMap()` + `MergeLine()` | `BoardModel.Move()`（纯 C#，原样搬） |
| `CheckGameState()` | 每次移动后调用一次（在 `Update` 的按键分支里） |
| `ShowMap()` | `BoardView.Refresh()`（第 5、6 章） |
| `AddRandomBlock()` 后的显示刷新 | 同上，由 `Refresh` 统一负责 |
| `Exit()` / 存档询问 | UI 按钮 + `PlayerPrefs`（第 7、8 章） |

注意最右边一列：**控制台里"一条直线"执行的流程，在 Unity 里变成了"每帧被引擎回调一次"的分散结构**。这就是为什么2048 实战 02要强调"逻辑与表现分离"——只有这样，你的算法才能原样搬过来而不被 Unity 的对象生命周期搅乱。
