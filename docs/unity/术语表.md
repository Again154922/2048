# Unity 术语表（遇到不认识的词就来这里查）

零基础学 Unity，最大的障碍其实不是代码，是**满屏的英文术语**。这份表按类别整理，每条只给"人话解释"，不展开。

## 核心概念（最重要）

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **GameObject** | 游戏对象 | 场景里的"一个东西"。它本身是个空壳，只有名字、标签和一堆组件 |
| **Component** | 组件 | 挂在 GameObject 上的"能力积木"：渲染、碰撞、你的脚本，全都是组件 |
| **Transform** | 变换 | 每个 GameObject **必定有**的组件，管位置/旋转/缩放 |
| **MonoBehaviour** | 行为脚本 | 你写的脚本要继承的基类。继承它才能挂到对象上、才能用 `Update` 这类回调 |
| **Prefab** | 预制体 | 可复用的对象模板（`.prefab` 文件）。改模板，所有实例跟着变 |
| **Instance** | 实例 | 由 Prefab（或 `Instantiate`）生成出来的具体对象 |
| **Scene** | 场景 | 一屏内容。一个游戏通常有多个场景（菜单场景、游戏场景……） |
| **Asset** | 资源 | `Assets` 目录里的一切：脚本、图片、Prefab、场景、音频…… |

## 编辑器界面

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **Hierarchy** | 层级 | 当前场景里所有对象的树形列表 |
| **Inspector** | 检视面板 | 显示选中对象的所有组件和字段，**改数值都在这里** |
| **Project** | 项目窗口 | `Assets` 目录的浏览器 |
| **Console** | 控制台 | 显示 `Debug.Log` 输出和报错。**程序出问题第一眼看这里** |
| **Scene 视图** | 场景视图 | 你搭建世界的地方 |
| **Game 视图** | 游戏视图 | 玩家实际会看到的画面（摄像机拍到的内容） |
| **Gizmo** | 辅助图标 | 场景里那些不是游戏内容的辅助图形：坐标轴、摄像机预览框、光照图标等 |

## 2D 与渲染

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **Sprite** | 精灵 | 2D 里的一张图（图片资源） |
| **SpriteRenderer** | 精灵渲染器 | 把 Sprite 画出来的组件 |
| **Pixels Per Unit（PPU）** | 每单位像素数 | 默认 100 表示"100 像素算 1 个世界单位" |
| **World unit** | 世界单位 | 游戏世界里的长度单位，和屏幕像素无关 |
| **Orthographic** | 正交投影 | 2D 摄像机用的投影方式，没有近大远小 |
| **Sorting Layer / Order in Layer** | 排序层/层内顺序 | 决定 2D 图谁盖在谁上面 |
| **Material** | 材质 | "怎么画"的配方（用哪个 Shader + 参数） |
| **Shader** | 着色器 | 真正执行绘制的程序。日常不用写，但要认识这个词 |
| **Canvas** | 画布 | UI 元素的容器，所有 UI 都必须放在它下面 |
| **RectTransform** | 矩形变换 | UI 专用版 Transform，多了宽高和锚点 |
| **Anchor** | 锚点 | UI 元素"相对父容器哪个位置"定位 |
| **Pivot** | 轴心 | 对象自己的"原点"（旋转和缩放围绕它发生） |
| **Render Pipeline** | 渲染管线 | 一整套渲染方案：`Built-in`（内置，最省心）、`URP`（新，需配置）、`HDRP`（高端 3D） |

## 脚本与代码

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **Lifecycle（回调）** | 生命周期 | 引擎在特定时机自动调用的方法：`Awake` / `Start` / `Update` / `OnDestroy`…… |
| **Update** | —— | 每帧被调用一次，你的"游戏循环" |
| **FixedUpdate** | —— | 固定时间间隔调用，只给物理用 |
| **LateUpdate** | —— | Update 全部跑完后调用，常用于摄像机跟随 |
| **Coroutine** | 协程 | "可以暂停、之后继续"的方法，用来做延时和动画 |
| **IEnumerator** | —— | 协程方法的返回类型，配合 `yield return` 使用 |
| **[SerializeField]** | 序列化字段 | 让 `private` 字段出现在 Inspector 里 |
| **Serialization（序列化）** | 序列化 | 把字段的值存进场景/Prefab 文件，重启后还在 |
| **Instantiate** | 实例化 | 用代码复制一个对象（Prefab → 实例） |
| **Destroy** | 销毁 | 删除对象（帧末生效） |
| **GetComponent** | —— | 取同一个对象上的组件 |
| **NullReferenceException** | 空引用异常 | 最常见报错：某个引用是 `null`（八成是 Inspector 里没拖） |
| **Script Execution Order** | 脚本执行顺序 | 手动指定多个脚本谁先执行 |

## 输入

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **Input Manager** | 旧输入系统 | 用 `Input.GetKeyDown(KeyCode.A)` 的那套，2022.3 默认启用 |
| **Input System Package** | 新输入系统 | 用 `InputAction` / `.inputactions` 资源的那套，手柄/重绑定更规范 |
| **KeyCode** | 键码 | 按键的枚举值，如 `KeyCode.Space`、`KeyCode.LeftArrow` |
| **Action（输入）** | 动作 | 新输入系统里"一个抽象动作"（比如"移动"），可以绑多个物理按键 |

## 物理（2048 用不到，但你会遇到）

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **Rigidbody / Rigidbody2D** | 刚体 | 让对象受重力/速度控制 |
| **Collider / Collider2D** | 碰撞体 | 定义对象的"碰撞形状" |
| **Trigger** | 触发器 | 只检测"进入/离开"，不产生物理反弹 |

## 音频

| 术语 | 中文 | 人话解释 |
| --- | --- | --- |
| **AudioClip** | 音频片段 | 一个音频文件 |
| **AudioSource** | 音源 | 播放音频的组件，挂在对象上 |
| **AudioListener** | 听者 | 摄像机默认带一个，代表"耳朵"（一个场景只能有一个） |

## 工作流与发布

| 术语                     | 中文      | 人话解释                                      |
| ---------------------- | ------- | ----------------------------------------- |
| **Play mode**          | 运行模式    | 点 ▶ 进入；**运行中的改动退出后全部丢失**                  |
| **Build**              | 构建      | 打包成可执行程序（Build Settings / Build Profiles） |
| **Player Settings**    | 播放器设置   | 公司名、产品名、图标、分辨率、输入系统开关都在这里                 |
| **PlayerPrefs**        | ——      | Unity 自带的小型键值存储（Windows 上写注册表），适合存分数设置    |
| **persistentDataPath** | 持久化数据目录 | 跨平台正确的"可写目录"，存档应该放这                       |
| **meta 文件**            | ——      | 每个资源旁的 `.meta`，存 GUID，**必须提交到 git**       |
| **Library**            | ——      | 导入缓存目录，可重建，**绝不能提交到 git**                 |
| **Domain Reload**      | 域重载     | 改脚本后编辑器重新加载代码，会卡一下                        |

## 最容易搞混的六组概念

| 容易混 | 区别 |
| --- | --- |
| **Scene vs Game 视图** | 前者是"编辑者视角"，后者是"玩家视角（摄像机拍到的）"。在 Scene 里挪动摄像机，Game 视图才会变 |
| **Transform.position vs localPosition** | 前者是世界坐标，后者是"相对父对象"的坐标。有父对象时两者不同 |
| **Hierarchy 里的眼睛 vs 勾选框** | 眼睛只影响编辑器里看不看得见；勾选框会让对象真的失效（脚本停止） |
| **GameObject vs Component** | 对象是"壳"，组件是"能力"。删组件对象还在，删对象组件全没 |
| **Sprite vs SpriteRenderer** | Sprite 是"图"，SpriteRenderer 是"把图画出来的组件" |
| **PlayerPrefs vs persistentDataPath** | 前者是 Unity 给的键值存储（小数据），后者是你可以放自己文件（JSON 等）的目录 |
