# 03　打磨表现：动画、UI、音效

前六章做出来的东西"能玩但很硬"：数字瞬间跳变、没有分数、没有结束提示。这一章把它变成像个游戏。

## 3.1 先想清楚：动画该由谁负责

动画属于**表现层**，绝不能反过来影响游戏逻辑。原则：

> **按下的那一刻，数据就已经算完了**；动画只是"把这次变化演出给人看"。

所以正确的顺序永远是：`Model.Move()` → 数据已定 → 播放动画 → 动画结束时再允许下一次输入。

这一点很重要，因为它决定了**动画期间要不要锁输入**。如果不锁，玩家连按三下方向键时，数据已经变了三次，动画还在播第一次——画面和数据会错位。所以做动画时必须引入一个 `_isAnimating` 状态。

## 3.2 两种动画方案（先选简单的）

### 方案 A：格子弹跳 / 淡入（推荐先做这个）

好处：改动极小，不碰数据结构。做法是给 `TileView` 加一点"变身"动画，在数字变化时播一下：

```csharp
using System.Collections;
using TMPro;
using UnityEngine;

public class TileView : MonoBehaviour
{
    [SerializeField] private SpriteRenderer background;
    [SerializeField] private TextMeshPro label;

    private int _value;
    private Coroutine _animation;

    // （颜色表同2048 实战 01，略）

    public void SetValue(int value, bool animate = true)
    {
        bool changed = value != _value;
        _value = value;

        label.text = value == 0 ? string.Empty : value.ToString();
        if (value != 0)
        {
            int index = Mathf.Clamp(Mathf.RoundToInt(Mathf.Log(value, 2)), 1, Colors.Length - 1);
            background.color = Colors[index];
        }

        if (!changed || !animate) return;

        // 数字变了：强制打断上一次动画，重新播一次
        if (_animation != null) StopCoroutine(_animation);
        _animation = StartCoroutine(PopRoutine());
    }

    /// <summary>先缩小再弹回原大小，给人"刚刚发生变化"的视觉反馈。</summary>
    private IEnumerator PopRoutine()
    {
        const float duration = 0.12f;

        Vector3 from = Vector3.one * 0.85f;
        Vector3 to = Vector3.one;

        float t = 0f;
        while (t < duration)
        {
            t += Time.deltaTime;
            transform.localScale = Vector3.Lerp(from, to, t / duration);
            yield return null;                  // 等下一帧继续
        }

        transform.localScale = to;              // 收尾归位，避免浮点误差累积
    }
}
```

注意几个专业细节：

- **`yield return null`** 表示"下一帧继续"，这是动画循环的正确写法（不是 `while(true)`，也不是线程）
- **先保存 `StopCoroutine`**：同一个对象上重复触发动画时，必须打断上一次，否则两条协程会抢着改 `localScale`，出现抖动
- **收尾时强制赋值**：`Vector3.Lerp` 的 `t/duration` 最后可能不精确等于 1，手动归位可以避免方块慢慢"缩水"

### 方案 B：真正的滑动（进阶，先了解思路）

原版 2048 里方块是**滑**到新位置的。要做到这个，现在这套"16 个固定格子对象"的结构就不够用了——格子对象固定在原地，"方块"得是独立的对象。

改造思路（等你想做的时候再动，改动不小）：

1. `Model` 的 `Move` 额外输出一张"移动映射"：`(fromX, fromY) → (toX, toY)`，以及哪些格子发生了合并
2. `BoardView` 维护"方块对象列表"（而不是格子列表），每帧根据映射播放位移
3. 合并的两个方块：一个滑到位后销毁，另一个更新数值并放大

代价是 Model 要暴露内部细节（破坏了现在的"只有数据"的纯净性），一般会用一个中间数据结构（比如 `MoveResult`）来传递。**建议先把方案 A 做完，玩顺了再升级。**

## 3.3 动画期间锁输入

有了动画，就要防止"连按方向键导致画面错位"。做法是在 `GameController` 里加一个状态：

```csharp
private bool _isBusy;   // 正在播放一次移动的全部表现

void Update()
{
    if (_isBusy) return;                      // 动画期间丢弃输入

    ...

    if (!_model.Move(direction.Value)) return;

    _model.AddRandomTile();
    _isBusy = true;
    StartCoroutine(PlayMoveThenUnlock());
}

private IEnumerator PlayMoveThenUnlock()
{
    view.Refresh(_model.Board);               // 内部各自播自己的小动画
    yield return new WaitForSeconds(0.15f);   // 等表现播完
    _isBusy = false;
    ...
}
```

> 另一种更"玩家友好"的做法不是丢输入，而是**排队**：把按下的方向存进一个队列，动画结束后立刻消费。原版 2048 就是这种手感（快速连按不会丢）。想做得更细可以把 `_isBusy` 换成一个 `Queue<Direction>`。

## 3.4 分数 UI：Canvas 与锚点

UI 和场景里的 Sprite 是两个世界：UI 元素**必须**放在 `Canvas` 下面（Canvas 是 UI 的根，它负责"把 UI 铺满屏幕"）。

### 步骤

1. Hierarchy 右键 → `UI → Canvas`（会自动生成一个 `EventSystem`，别删，按钮点击依赖它）
2. 选中 Canvas，`Canvas Scaler` 组件里把 `UI Scale Mode` 改成 **Scale With Screen Size**，参考分辨率设 `1920×1080`——这样不同分辨率下 UI 不会大小失控
3. 右键 Canvas → `UI → Text - TextMeshPro`，命名 `ScoreText`
4. 选中 `ScoreText`，在 Inspector 的 Rect Transform 里：
   - 点左上角的**锚点方块**，选 `top-left`
   - 设 `Pos X = 40`、`Pos Y = -40`、宽 400、高 80
   - 字体大小 48、左对齐
5. 复制一份命名 `BestText`，Y 改成 `-130`，作为历史最高

### 锚点（Anchor）到底是什么

一句话：**锚点决定"我相对父容器的哪个位置定位"**。

- 锚点设 `top-left` + `Pos (40, -40)`：不管屏幕多大，我永远离左上角 40 像素
- 锚点设 `center`：我永远在屏幕正中
- 拉伸模式（锚点的四个角分开，比如左右都贴边）：宽度随屏幕变化——做血条那种常用

新手把 UI 做歪，几乎都是锚点没设对。

### 让分数动起来

在 `GameController` 里加两个引用，每次刷新后同步：

```csharp
using TMPro;
using UnityEngine;

public class GameController : MonoBehaviour
{
    [SerializeField] private BoardView view;
    [SerializeField] private TextMeshProUGUI scoreText;
    [SerializeField] private TextMeshProUGUI bestText;

    private BoardModel _model;
    private int _best;                 // 历史最高，2048 实战 04会存到磁盘

    private void RefreshAll()
    {
        view.Refresh(_model.Board);

        int score = _model.Sum();      // 用"所有方块之和"当分数，简单直观
        if (score > _best)
        {
            _best = score;
        }

        scoreText.text = $"分数 {score}";
        bestText.text = $"最高 {_best}";
    }
}
```

> **分数的两种算法**：① 所有方块之和（你现在这种做法，2026 版很多实现都用）；② 累计"每次合并产生的数字"（原版 2048 用这个，数字更大更好看）。第二种需要在 `MergeLine` 里把"合并出的值"累加出来，`MergeLine` 得改成返回 `(int[] line, int gained)` 或用一个 `ref` 参数。想更像原版就做第二种。

## 3.5 游戏结束面板

1. 右键 Canvas → `UI → Panel`，命名 `GameOverPanel`，颜色调成半透明黑
2. 在它下面加一个 `TextMeshPro`（"游戏结束"）和一个 `Button`（"再来一局"）
3. 选中 `GameOverPanel`，把它在 Inspector 左上角**取消勾选**（禁用状态）——运行时再启用
4. 写脚本挂到 Panel 上：

```csharp
using TMPro;
using UnityEngine;
using UnityEngine.UI;

public class GameOverPanel : MonoBehaviour
{
    [SerializeField] private TextMeshProUGUI messageText;
    [SerializeField] private Button restartButton;

    private System.Action _onRestart;

    void Awake()
    {
        // 注意：按钮的点击事件用代码绑定，比在 Inspector 里连线更好维护
        restartButton.onClick.AddListener(() => _onRestart?.Invoke());
        gameObject.SetActive(false);
    }

    public void Show(int maxValue, System.Action onRestart)
    {
        _onRestart = onRestart;
        messageText.text = $"游戏结束\n本局最大 {maxValue}";
        gameObject.SetActive(true);
    }

    public void Hide()
    {
        gameObject.SetActive(false);
    }
}
```

然后在 `GameController` 里：

```csharp
[SerializeField] private GameOverPanel gameOverPanel;

// 检测到游戏结束时
if (!_model.CanMove())
{
    gameOverPanel.Show(_model.MaxValue(), Restart);
}

private void Restart()
{
    gameOverPanel.Hide();
    _model.Reset();
    RefreshAll();
}
```

> **控制台版对照**：控制台里"游戏结束"就是在第六行打印一句话，玩家按 R 继续；Unity 里换成"禁用/启用一个 UI 面板 + 按钮回调"。逻辑位置是一样的（都在每次移动之后检查 `CanMove`）。

## 3.6 音效

最简单的方式：

1. 选中 `Board`（或任一常驻对象），Add Component → `Audio Source`，**取消勾选 Play On Awake**
2. 把音效文件拖进 `Assets`（`.wav` / `.ogg` / `.mp3`）
3. 在 `GameController` 里：

```csharp
[SerializeField] private AudioSource audioSource;
[SerializeField] private AudioClip moveClip;
[SerializeField] private AudioClip mergeClip;

// 移动成功时
audioSource.PlayOneShot(moveClip, 0.6f);
// 发生合并时（需要 Model 告诉你这次有没有合并）
audioSource.PlayOneShot(mergeClip, 0.8f);
```

`PlayOneShot` 的好处是**多个音效可以重叠播放**（连续按方向键时不会互相打断），适合这种短促音效。

音效文件从哪来：freesound.org、opengameart.org 都有 CC0 素材；懒得找的话，先用 Unity 自带的 `Assets → Create → Audio → ...` 不行，那就**先跳过音效**——音效是锦上添花，不影响你学结构。
