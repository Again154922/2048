# 06　2D 世界：坐标、Sprite、摄像机与输入

## 6.1 2D 坐标系：世界单位不是像素

Unity 是 3D 引擎，2D 只是"摄像机正对着 XY 平面"的一种情况：

- **X 向右为正，Y 向上为正，Z 指向屏幕里**
- 2D 里 Z 基本不用管，但**它决定谁盖在谁上面**：摄像机在 `z = -10` 看向 `+z`，所以 Z 越小离摄像机越近、越靠前画
- 控制遮挡关系更常用的手段是 `SpriteRenderer` 的 **Order in Layer**（数值大的画在上面）

关键概念：**世界单位（unit）不是像素**。默认导入图片用 **100 Pixels Per Unit (PPU)**，即"100×100 像素的图 = 1 个世界单位"。所以 `transform.position = new Vector3(1, 0, 0)` 是"往右挪 1 个世界单位"。一张 512×512 的图默认占 5.12 个世界单位，屏幕上会显得巨大——这是新手第一个"我的图怎么这么大"的原因。

**好处**：游戏逻辑可以放心用"格"为单位，改分辨率不影响逻辑。2048 就把**一格定为 1 个世界单位**。

## 6.2 摄像机：决定你能看见什么

2D 模板里 `Main Camera` 的默认值：

| 属性 | 值 | 含义 |
| --- | --- | --- |
| Projection | Orthographic | 正交投影，2D 必须用这个（没有近大远小） |
| Size | 5 | **可见高度的一半**，所以默认能看到 10 个世界单位高 |
| Position | (0, 0, -10) | 看向原点 |

视野推算：高度 = `Size × 2`；宽度 = 高度 × 屏幕宽高比（16:9 时约 17.8 个单位宽）。

**2048 建议**：每格 1 个单位 → 棋盘 4×4，把摄像机 **Size 设成 3.5～4**，棋盘就舒服地占满屏幕中间。想直观看到范围：选中摄像机，Scene 视图里会出现一个白色框，那就是可视区域。

## 6.3 Sprite 与 SpriteRenderer

Sprite 是 2D 图片资源。把 PNG 拖进 `Assets` 后，Inspector 里要认识的几个：

| 设置 | 默认 | 什么时候改 |
| --- | --- | --- |
| Texture Type | Sprite (2D and UI) | 2D 模板下默认就对 |
| Pixels Per Unit | 100 | 想改变图片实际尺寸时改它（比改 Scale 更"正"） |
| Filter Mode | Bilinear | 像素风改 **Point (no filter)** |
| Compression | Normal Quality | 要清晰就 None |

**SpriteRenderer** 负责把 Sprite 画出来：

| 属性 | 作用 |
| --- | --- |
| Sprite | 显示哪张图 |
| Color | 给图染色 |
| Order in Layer | 越大越靠前 |
| Flip X/Y | 翻转 |

> **2048 的省事方案**：方块不需要美术资源。用 Unity 内置的 `Square`（`Assets → Create → 2D → Sprites → Square`），靠 `SpriteRenderer.Color` 区分数值大小，数字用文本组件显示。零美术资源也能做出能看的效果。

## 6.4 让一个方块出现在屏幕上

1. Hierarchy 右键 → `2D Object → Sprites → Square`，命名 `Tile`
2. 选中它：Position 设 `(0,0,0)`，Scale 设 `(0.95, 0.95, 1)`（留缝），SpriteRenderer 的 Color 设成喜欢的颜色
3. 现在它铺满视野——选中摄像机，Size 改成 `4`，再看 Game 视图
4. 给 `Tile` 加数字：右键 `Tile` → `UI → Text - TextMeshPro`（首次会提示导入 TMP Essentials，点是），内容改成 `2`，字号调大

关于文字：`TextMeshProUGUI` 是给 Canvas 用的，直接当子对象放在 Sprite 上容易错位。**2048 更方便的是用世界坐标版的 `TextMeshPro`**（Add Component 里搜 `TextMeshPro`，不带 UGUI），它跟着父对象走、吃世界坐标，最省心。

## 6.5 输入：新旧两套系统

| | 旧：Input Manager | 新：Input System Package |
| --- | --- | --- |
| 用法 | `Input.GetKeyDown(KeyCode.A)` | `InputAction` + `.inputactions` 资源 |
| 状态 | **2022.3 新建项目默认启用** | 要装包并切换 |
| 成本 | 极低，你已经在用 | 中等（Action / Binding / 上下文） |
| 优点 | 简单直接 | 手柄、多设备、重绑定更规范 |

开关在 `Edit → Project Settings → Player → Other Settings → Active Input Handling`。

**建议**：2048 只需要键盘，**继续用旧输入系统**，把精力放在游戏结构上。等要做手柄支持或输入重绑定时再学 Input System（切换前备份项目，切错会让所有 `Input.GetKeyDown` 编译报错）。

## 6.6 最常用的输入 API

```csharp
// 键盘
Input.GetKeyDown(KeyCode.LeftArrow)   // 这一帧刚按下（只触发一帧）← 2048 主要用这个
Input.GetKey(KeyCode.LeftArrow)       // 一直按住（每帧 true）
Input.GetKeyUp(KeyCode.LeftArrow)     // 这一帧刚松开
KeyCode.W / A / S / D / R / Escape

// 鼠标
Input.GetMouseButtonDown(0)           // 0 左键、1 右键、2 中键
Input.mousePosition                   // 屏幕像素坐标，左下角是 (0,0)

// 轴（键盘的 A/D/← → 的封装）
float h = Input.GetAxisRaw("Horizontal");   // -1 / 0 / 1
```

**必须记住**：`GetKeyDown` 只在按下的那一帧为 true，所以它**必须写在 `Update` 里**（每帧都查），不能写在 `FixedUpdate`（可能错过），也不能写在"等一会儿再查"的地方。

### 长按连续移动的正确写法

2048 里"按住方向键反复移动"是可选的。做法**不是**开线程，而是在 `Update` 里用时间累加：

```csharp
private float _repeatTimer;
private const float FirstDelay = 0.35f;   // 按住后先等一会儿
private const float RepeatRate = 0.12f;   // 之后每次的间隔

void Update()
{
    Direction? dir = InputReader.ReadDirection();
    if (dir == null) { _repeatTimer = 0f; return; }

    if (Input.GetKeyDown(KeyCodeFor(dir.Value)))
    {
        TryMove(dir.Value);
        _repeatTimer = FirstDelay;
    }
    else
    {
        _repeatTimer -= Time.deltaTime;
        if (_repeatTimer <= 0f)
        {
            TryMove(dir.Value);
            _repeatTimer = RepeatRate;
        }
    }
}
```

**这就是"取消后台线程"的替代方案**：状态是普通字段，时间推进用 `Time.deltaTime`，一切都在主线程的 `Update` 里。

## 6.7 2048 的输入需求梳理

先想清楚要什么，再写代码：

| 输入 | 行为 | 备注 |
| --- | --- | --- |
| ← / A、→ / D、↑ / W、↓ / S | 对应方向移动 | 方向键和 WASD 都行 |
| R | 重开一局 | 控制台版是直接重开 |
| Esc | 退出 / 打开菜单 | `Application.Quit()` 只在打包后有效 |
| Z（可选） | 撤销一步 | 存一个上一步棋盘快照即可，比控制台版更容易做 |

```csharp
using UnityEngine;

public enum Direction { Left, Up, Right, Down }

public static class InputReader
{
    /// <summary>返回这一帧按下的方向键，没有按下则为 null。</summary>
    public static Direction? ReadDirection()
    {
        if (Input.GetKeyDown(KeyCode.LeftArrow)  || Input.GetKeyDown(KeyCode.A)) return Direction.Left;
        if (Input.GetKeyDown(KeyCode.RightArrow) || Input.GetKeyDown(KeyCode.D)) return Direction.Right;
        if (Input.GetKeyDown(KeyCode.UpArrow)    || Input.GetKeyDown(KeyCode.W)) return Direction.Up;
        if (Input.GetKeyDown(KeyCode.DownArrow)  || Input.GetKeyDown(KeyCode.S)) return Direction.Down;
        return null;
    }
}
```

用可空枚举 `Direction?` 表达"可能没有方向"，比用 `-1` 之类的魔法值干净。

## 6.8 对照你的 2048

| 控制台版（v2.0） | Unity 版 |
| --- | --- |
| `Console.ReadKey(true)` 阻塞等一个键 | `Update()` 里 `Input.GetKeyDown` 非阻塞查询（引擎替你"等"） |
| `switch (keyInfo.Key)` 分派方向 | `InputReader.ReadDirection()` 返回枚举 |
| `ConsoleKey.LeftArrow` | `KeyCode.LeftArrow` |
| `Console.WindowWidth` 手算排版列宽 | 摄像机 Size + 世界坐标（不用再算列宽） |
| 每格固定 8 列文本输出 | 每个方块一个对象，位置由 `Vector3` 决定 |

**最爽的变化**：控制台版为了让数字对齐，你写了 `PadRight(8)`、算了棋盘 32 列、还要防"影子字符"；Unity 里这些统统不需要——方块有自己的位置，对不对齐由你摆放决定。
