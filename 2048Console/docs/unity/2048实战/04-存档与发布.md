# 04　存档与发布

你在控制台版里做了 `2048-best.txt`（历史最高）和 `2048-save.txt`（进度存档），都放在 exe 同目录。Unity 里**思路一样，落地方式不同**，因为这章的坑主要集中在"文件放哪"和"什么时候能交互"。

## 4.1 文件该放哪：`Application.persistentDataPath`

**不要**再往 exe 目录写文件。原因：

- 打包后程序可能装在 `C:\Program Files\...`，普通权限**写不进去**
- macOS / Linux / Android / iOS 下"exe 同目录"这个概念根本不成立

Unity 给了一个跨平台都正确的可写目录：

```csharp
string path = Application.persistentDataPath;
// Windows 上实际是：C:\Users\<用户名>\AppData\LocalLow\<公司名>\<产品名>\
Debug.Log(path);        // 先把这个路径打出来，之后调试全靠它
```

把公司名/产品名设好（`Edit → Project Settings → Player → Company/Product Name`），这个目录就固定了。你控制台版是"文件跟着 exe 走"，Unity 版是"文件固定在用户目录"，**这是仅有的实质差别**。

## 4.2 历史最高：用 `PlayerPrefs` 就够

存一个整数不需要自己管文件：

```csharp
private const string BestKey = "best_score";

// 读（第一次运行时给默认值 0）
_best = PlayerPrefs.GetInt(BestKey, 0);

// 写（值变化后调用）
PlayerPrefs.SetInt(BestKey, _best);
PlayerPrefs.Save();        // 立刻落盘；不调用的话退出时才会自动写
```

`PlayerPrefs` 在 Windows 上写进**注册表**（`HKCU\Software\<公司名>\<产品名>`），只适合放小的配置/分数。它的缺点：用户重置系统、换电脑就没了。**历史最高用它是合适的**，和你控制台版的 `2048-best.txt` 是同一类东西。

> 想和文件保持一致，也可以自己写 `File.WriteAllText(Path.Combine(Application.persistentDataPath, "best.txt"), best.ToString())`。**两种都行**，`PlayerPrefs` 更省事，文件更透明（能被玩家看见/备份）。

## 4.3 存档：JSON + 文件（这里有个 Unity 的坑）

想存整个棋盘（对应你的 `2048-save.txt`），推荐 JSON：

```csharp
using System;
using System.IO;
using UnityEngine;

/// <summary>存档数据。JsonUtility 要求：public 字段 或 [SerializeField] 私有字段，且类型可序列化。</summary>
[Serializable]
public class SaveData
{
    public int[] cells = new int[16];   // 二维数组摊平成一维：index = x * 4 + y
    public int score;
    public int best;
    public string savedAt;              // 存个时间戳，方便展示"上次保存于……"
}

public static class SaveSystem
{
    private static string SavePath => Path.Combine(Application.persistentDataPath, "save.json");
    private static string BestPath => Path.Combine(Application.persistentDataPath, "best.txt");

    public static void Save(BoardModel model, int best)
    {
        SaveData data = new SaveData
        {
            score = model.Sum(),
            best = best,
            savedAt = DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss"),
        };

        // int[,] 展平成一维：JsonUtility 不支持二维数组
        for (int x = 0; x < BoardModel.Size; x++)
        {
            for (int y = 0; y < BoardModel.Size; y++)
            {
                data.cells[x * BoardModel.Size + y] = model.Board[x, y];
            }
        }

        string json = JsonUtility.ToJson(data, prettyPrint: true);
        File.WriteAllText(SavePath, json);
        File.WriteAllText(BestPath, best.ToString());
    }

    public static bool TryLoad(out SaveData? data)
    {
        data = null;
        try
        {
            if (!File.Exists(SavePath)) return false;
            data = JsonUtility.FromJson<SaveData>(File.ReadAllText(SavePath));
            return data != null && data.cells != null && data.cells.Length == 16;
        }
        catch (Exception e)
        {
            Debug.LogWarning($"存档读取失败：{e.Message}");
            return false;
        }
    }

    public static void Delete()
    {
        if (File.Exists(SavePath)) File.Delete(SavePath);
    }
}
```

**`JsonUtility` 的限制**（新手必踩）：

| 不能做的事 | 替代方案 |
| --- | --- |
| 序列化二维数组 `int[,]` | 展平成一维（上面就是这么做的） |
| 序列化 `Dictionary` | 拆成两个数组（keys / values） |
| 序列化属性（`public int Score { get; set; }`） | 用字段 |
| 序列化 `null` 的引用类型 | 初始化为空数组/空字符串 |

从存档恢复棋盘：

```csharp
public void LoadFrom(SaveData data)
{
    for (int x = 0; x < Size; x++)
    {
        for (int y = 0; y < Size; y++)
        {
            _board[x, y] = data.cells[x * Size + y];
        }
    }
}
```

## 4.4 ⚠️ 一个必须知道的差异：Unity 里"退出时询问"几乎不可行

你的控制台版做得很好：按 Esc → 问"是否保存" → 存完再退。但 Unity 里**不能这么干**：

`OnApplicationQuit()` 触发时，窗口已经在关闭流程中，**无法再弹出一个可交互的确认框**（玩家点了右上角 ×，你没机会问）。强行弹 UI 只会闪一下。

所以 Unity 游戏的标准做法是这三选一：

| 方案 | 做法 | 适合 |
| --- | --- | --- |
| **自动存档**（最常用） | 每次有效移动后写一次 `save.json` | 2048 这种"状态极小、写起来飞快"的游戏，首选 |
| 菜单里手动保存 | Esc 打开暂停菜单，里面有"保存""保存并退出""返回主菜单" | 需要玩家控制存档时机 |
| 定期自动保存 | 每 N 步或每 30 秒存一次 | 状态较大的游戏 |

**建议**：2048 直接**每次移动后自动保存**，退出时什么都不用做——玩家下次打开游戏，直接问"发现上次进度，是否继续？"。这比控制台版的"退出时询问"体验更好，而且实现更简单。

```csharp
// GameController.Update() 里，一次成功的移动之后
if (!_model.Move(direction.Value)) return;
_model.AddRandomTile();
RefreshAll();

SaveSystem.Save(_model, _best);       // 自动存档，一行搞定
```

而对"是否继续上次进度"，用一个开局弹窗：

```csharp
void Start()
{
    if (SaveSystem.TryLoad(out SaveData? data) && data != null)
    {
        continuePanel.Show(data.savedAt, onContinue: () => { _model.LoadFrom(data!); RefreshAll(); },
                                        onNewGame: () => { SaveSystem.Delete(); Restart(); });
    }
    else
    {
        Restart();
    }
}
```

## 4.5 打包发布

1. `File → Build Settings`（新版叫 Build Profiles，逻辑一样）
2. 把 `SampleScene` 拖进 `Scenes In Build`（**不拖进去的话打包出来的游戏是黑屏**，这是新手第一大坑）
3. Platform 选 `Windows, Mac, Linux` → Target Platform `Windows`、Architecture `x86_64`
4. `Player Settings` 里检查：
   - Company Name / Product Name（决定 `persistentDataPath` 的位置，**发布后就别改了**，改了玩家的存档会"消失"）
   - `Resolution and Presentation`：全屏还是窗口化、默认分辨率
   - 图标
5. 点 `Build`，选一个空文件夹（比如 `F:\unity\build\2048`）

产物是一个文件夹：`2048.exe` + `2048_Data\` + `UnityPlayer.dll` 等。**必须整个文件夹一起发**，不能只发 exe（这一点和控制台的"单文件发布"完全不同）。

> 想要单文件？Unity 官方没有这个功能。想做成一个 exe 得用第三方打包器（Enigma Virtual Box 之类），不建议折腾。

## 4.6 对照你的 2048

| 控制台版 | Unity 版 |
| --- | --- |
| `2048-best.txt` 放 exe 同目录 | `PlayerPrefs` 或 `persistentDataPath\best.txt` |
| `2048-save.txt`：Esc 时询问后保存 | 每次移动自动保存 `persistentDataPath\save.json`（退出时无法询问） |
| 存档是 4 行数字文本 | JSON（更结构化，方便以后扩展字段） |
| 启动时检测文件并询问"是否继续" | 一样的思路，只是换成 UI 弹窗 |
| `dotnet publish` 出单个 exe | Build Settings 出**一个文件夹**，要整个发 |

## 4.7 本章动手

1. 在 `Awake` 里 `Debug.Log(Application.persistentDataPath)`，运行后去那个目录看看到底在哪
2. 接上 `PlayerPrefs` 存历史最高，重启游戏确认还在
3. 接上 `SaveSystem`，每次移动后自动存档，重启游戏确认棋盘被还原
4. 打包一次 Windows 版本，发给朋友（或自己）在一个新目录里解压运行，确认存档依然工作
