# 02　编辑器入门：项目结构与五大窗口

## 2.1 你机器上已经有什么

| 东西 | 位置 | 作用 |
| --- | --- | --- |
| Unity Hub 3.22.3 | `C:\Users\james\AppData\Roaming\UnityHub`（数据目录） | 管理版本、装编辑器、打开项目列表 |
| Unity Editor 2022.3.62f1 | `D:\APPS\Unity\2022.3.62f1` | 真正的编辑器，日常用的就是它 |
| 你已有的项目 | `F:\unity\...` | Stopwatch、UnityTest、ChatBox、UnoCards |

**Hub 和 Editor 的分工**：Hub 是"启动器 + 版本管理"，你双击 `Unity.exe` 或从 Hub 打开项目都行。日常入口是 Hub：它能记住项目列表（你之前那几个项目就躺在 Hub 的列表里），也负责装新版本和模块。

> 装模块（比如"Windows Build Support"）在 Hub 里：Installs → 齿轮 → Add modules。2022.3 默认就带 Windows 构建支持，一般不用管。

## 2.2 新建 2048 项目

1. Hub → Projects → **New project**
2. 编辑器版本选 `2022.3.62f1`
3. 模板选 **2D (Core)**——不要选 3D，也别选 2D URP（URP 是渲染管线，我们这种纯 2D 小游戏用不到，它只会多出一堆配置文件）
4. 名字 `2048`，位置 `F:\unity`（这样路径是 `F:\unity\2048`，和你其他项目并列）

创建完 Unity 会自己打开。第一次打开一个空 2D 项目，你会看到 `Main Camera` 和一个 `SampleScene`。

> **为什么选 2D 模板而不是 3D**：2D 模板的摄像机是正交投影（Orthographic），场景视图默认 2D 模式，新建图片默认导入成 Sprite。3D 模板里这些都要手动改，新手容易在第一关就卡住。

## 2.3 项目目录里哪些是"你的东西"

新建之后目录大致是这样：

```
F:\unity\2048\
├── Assets\            ← 你做的所有东西：脚本、图片、场景、Prefab、材质……（唯一必须进版本控制）
├── Packages\          ← 清单文件 manifest.json（哪些官方包被引用，要进版本控制）
├── ProjectSettings\   ← 项目设置（输入、分辨率、Player 设置……，要进版本控制）
├── Library\           ← 导入资源后的缓存，Unity 生成，可随时重建（很大，绝不进版本控制）
├── Temp\              ← 临时文件
├── Logs\              ← 日志
├── obj\               ← C# 编译中间产物
└── UserSettings\      ← 你个人的编辑器布局偏好（通常不进版本控制）
```

一句话记法：**`Assets` + `Packages` + `ProjectSettings` 是你的项目，其余全是缓存**。

这和你写控制台项目的直觉不一样：C# 项目的"源码即一切"，而 Unity 项目里**场景和 Prefab 是二进制/文本混合的资源文件**，`Assets` 目录本身就是"源码"。所以 Unity 项目的 `.gitignore` 要排除 `Library/`、`Temp/`、`obj/`、`Logs/`、`UserSettings/`。

> 如果以后要给 2048 项目建 git 仓库，直接用一个 Unity 专用 `.gitignore`（GitHub 上的 `github/gitignore` 里有 `Unity.gitignore`）。你已经有 `.gitignore` 的经验了，注意别把 `Assets/*.meta` 排除掉——**每个资源旁边的 `.meta` 文件必须提交**，它存的是资源的 GUID，丢了引用就全断。

## 2.4 五个窗口先认清楚

打开项目后，默认布局里最重要的五个窗口：

| 窗口 | 中文习惯叫法 | 干什么用的 | 类比到你的控制台项目 |
| --- | --- | --- | --- |
| **Hierarchy** | 层级 | 列出**当前场景**里的所有 GameObject | 像 `Console` 里的 `s_map` 里有哪些格子，但它是树形结构 |
| **Scene** | 场景视图 | 3D/2D 视图，拖拽摆放物体 | 你在脑子里想的那张棋盘 |
| **Game** | 游戏视图 | 运行时玩家看到的画面 | 控制台窗口本身 |
| **Inspector** | 属性面板 | 选中对象的**所有组件和字段** | 像调试器里展开一个对象看字段 |
| **Project** | 项目 | `Assets` 目录的浏览器 | 解决方案资源管理器 |

外加一个一定会常用到的：

| 窗口 | 作用 |
| --- | --- |
| **Console** | 显示 `Debug.Log` 输出和错误。**报错必看**，Unity 的错误经常是"某个引用没拖上" |

布局乱了或者关了窗口：`Window → General → ...` 找回来，或者 `Window → Layouts → Default` 一键复位。

## 2.5 场景（Scene）是什么

**一个场景 = 一个关卡/一屏界面**。你的 Stopwatch 项目里就一个场景，ChatBox 里有登录场景、注册场景等（如果做了切换的话）。

场景文件是 `Assets` 下的 `xxx.unity`。双击就能打开切换。文件本身是 YAML 文本，你也可以用文本编辑器打开看，但**千万别手改**。

2048 只需要一个场景就够了。将来要做"开始菜单 → 游戏 → 结算"多屏，才需要多个场景配合 `SceneManager.LoadScene()`。

## 2.6 Play 模式：三个必须记住的陷阱

点左上角的 ▶ 就进入运行模式，再点一次退出。这里有三条新手必踩的规则：

**① 运行中做的改动，退出后全部还原。**
运行模式下你在 Inspector 里改的参数、在 Hierarchy 里拖动的对象，退出 Play 后**全部回滚**。这是好事（方便试验），但很多人试出满意的数值忘了记下来，一退出就白干。

**② 运行中改 Script 里的 public 字段，退出后保留；改在代码里 new 出来的东西，不保留。**
准确说：Inspector 里那些**序列化字段**的值，运行时改了之后有时会"粘住"（尤其 `[SerializeField]` 的值和数组/列表），偶尔需要重置组件。如果发现"我明明改成 5 了它还是 3"，去 Inspector 里右键组件 → Reset，或者确认你改的是不是被代码在 `Start()` 里覆盖了。

**③ 运行中修改 C# 脚本 → Unity 会重新编译 → 会卡一下、有时脚本状态丢失。**
这点和控制台项目完全不同：那里你改代码要重新 `dotnet run`；这里 Unity 会自动重编译并重新加载，代价是编辑器会短暂卡顿（"domain reload"）。**建议：调试时尽量在 Play 前把代码写好，减少运行中改代码**。

## 2.7 你的第一个"Hello"——但别用 Debug.Log 刷屏

新建脚本的标准流程：

1. Project 窗口 → `Assets` 下右键 → Create → C# Script，命名 `Hello`
2. 双击打开（会在 Rider / VS / VS Code 里打开，取决于你的 External Editor 设置）
3. 把脚本**拖到 Hierarchy 里某个对象的 Inspector 上**，或者选中对象 → Add Component → 搜脚本名

```csharp
using UnityEngine;

public class Hello : MonoBehaviour
{
    void Start()
    {
        Debug.Log("场景加载后第一次执行，只执行一次");
    }

    void Update()
    {
        // 每帧都会执行！这里千万别写 Debug.Log，否则 Console 会被刷爆
    }

    void OnMouseDown()
    {
        Debug.Log("鼠标点到了这个对象");
    }
}
```

**文件名必须和类名完全一致**（`Hello.cs` ↔ `class Hello`）。你 F:\unity 里的 `Main Camera.cs`（类叫 `MainCamera`）、`Go Login Btn.cs`、`Event Listener.cs` 都是不匹配的——这种脚本 Unity 有可能拒绝挂载，或者在某些版本下能挂但行为诡异。这条规则是硬性的，**文件名和类名一模一样，且不要有空格**。

## 2.8 对照你的 2048：这一章对应的决策

| 控制台版的做法 | Unity 里的对应 |
| --- | --- |
| `2048.sln` + 几个 `.csproj` | 一个 Unity 项目（`.sln` 由 Unity 自动生成，不用管） |
| `Program.cs` 单文件 | 一个场景 + 若干脚本，每个脚本挂在不同对象上 |
| 整个游戏就是 1 个进程的 `while` 循环 | 游戏 = 场景里的一堆对象在**同一帧里各干各的** |
| 屏幕左上角画 4×4 文本网格 | 场景里 16 个（最多）方块对象，排成 4×4 |
