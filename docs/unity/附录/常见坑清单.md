# 常见坑速查清单（Unity 踩坑速查）

出事时从头往后看，八成能对上号。

## 脚本与编译

1. **文件名必须等于类名**，且不能有空格。`Main Camera.cs` 里写 `class MainCamera` 是错的——你项目里就有这种，建议改名。
2. **一个文件里只能有一个和文件同名的 MonoBehaviour**，但可以有别的普通类 / 枚举（比如 `Direction`）。
3. **改了代码编辑器不重新编译**：先看 Console 有没有编译错误（有错时 Unity 会拒绝进入 Play，很多人以为"点了没反应"）。
4. **`NullReferenceException` 最先怀疑"Inspector 里引用没拖"**。尤其是 Prefab 上的引用：要在 Prefab 本体上设好并 Apply。
5. **Unity 的 API 只能在主线程调用**（`Input`、`Transform`、`Instantiate`、`Debug.Log`…）。看到 `Task.Run` / `Thread` / `async void` 直接警觉——你在 `Stopwatch.cs`、`Main Camera.cs` 里踩过这个。
6. **`static` 字段在编辑器里不重置**：退出 Play 再进，值还是上次的（静态字段属于"域"，Unity 默认不会重载域）。所以别用静态字段存游戏状态——那是你 `KeyStatus` 的隐患。要重置就在 `[RuntimeInitializeOnLoadMethod]` 或 `Awake` 里显式清。
7. `Update` 里写 `Debug.Log` 会刷屏，也不方便定位——需要时用 `Time.frameCount` 采样，或者干脆用断点。

## 编辑器与场景

8. **运行中的改动退出后全部丢失**（包括 Inspector 的数值、Hierarchy 的结构）。想保留就先退出 Play 再改。
9. **场景没保存**：改完场景记得 `Ctrl+S`（标题栏有 `*` 就是未保存）。
10. **`Assets` 里资源旁边的 `.meta` 文件不能删、要进版本控制**，它保存 GUID，丢了引用就断。
11. **`Library` / `Temp` / `obj` 不要提交**，也**不要手动删 `Assets` 以外的目录来找"修复"**（真出问题删 `Library` 让 Unity 重建是最后手段）。
12. **Prefab 的 override**：在场景实例上改的东西如果不想只影响这一个实例，记得 Apply。Inspector 里带蓝色竖条的字段就是 override。
13. **同一个对象上多个脚本的 `Update` 顺序不确定**，不要依赖；需要顺序就合并脚本或设置 Script Execution Order。
14. **`SetActive(false)` 的对象里脚本不会执行**（`Awake`/`Start` 都不会），但字段值保留。

## 游戏逻辑

15. **输入用 `GetKeyDown` 就别写在 `FixedUpdate`**（会漏）。`FixedUpdate` 只给物理用。
16. **`GetKeyDown` 只在按下那一帧为 true**，写在协程里"等一会儿再查"会丢。
17. **移动相关一定要乘 `Time.deltaTime`**，否则帧率不同速度不同。
18. **别用 `DateTime.Now` 做游戏内计时**，用 `Time.time` / `Time.deltaTime`（受 `timeScale` 控制，能暂停）。
19. **`Instantiate` 出来的对象要记得归属父对象**（`Instantiate(prefab, transform)`），否则它会堆在场景根部，想整体清空时很麻烦。
20. **`Destroy` 是帧末生效**：同一个 `Update` 里销毁了对象，这一帧它还在。
21. **不要每帧 `GameObject.Find`**：很慢，应该在 `Awake`/`Start` 里缓存引用。
22. **`int[,]` 和 `int[][]` 不一样**：前者是二维数组（Unity 场景里更常用），后者是数组的数组（你控制台版用的）。`JsonUtility` 只认一维数组。
23. **合并类逻辑一定要"一个块一轮只合并一次"**：这就是 `justMerged` 标记存在的理由，`[2,2,2,2]` 必须是 `[4,4]` 而不是 `[8]`。你在控制台版为这个 bug 返工过。

## 协程

24. **协程不会在对象被禁用/销毁后继续**（宿主没了协程自动停），这是好事，但要知道。
25. **同一个对象上重复启动动画协程前先 `StopCoroutine`**，否则两个协程抢改同一个属性会抖。
26. **`WaitForSeconds` 受 `Time.timeScale` 影响**，暂停时（`timeScale = 0`）它会永远等下去。UI 动画要用 `WaitForSecondsRealtime`。
27. **协程不是线程**，它跑在主线程上，别在协程里写耗时几十毫秒的循环（会卡帧）。

## UI

28. **UI 元素必须在 Canvas 下**，否则不显示。
29. **锚点（Anchor）决定定位基准**：锚点设错，改分辨率 UI 就跑飞。
30. **`TextMeshPro` 和 `TextMeshProUGUI` 是两个东西**：前者吃世界坐标（场景里的 3D 文本），后者在 Canvas 里用。混用会出现"文字看不到/位置诡异"。
31. **Canvas Scaler 用 Scale With Screen Size**，并设参考分辨率，UI 才不会被高 DPI 屏幕搞乱。
32. **按钮点击不响应**：场景里缺 `EventSystem`（UI → EventSystem）、或者有别的 UI 元素盖在上面（Canvas 的 `Raycast Target`）。
33. **UI 挡不住鼠标**：检查 `Graphic Raycaster` 组件。
34. **屏幕坐标 ≠ 世界坐标**：`Input.mousePosition` 是屏幕像素坐标，要转世界坐标用 `Camera.main.ScreenToWorldPoint(...)`，而且**必须给 Z**（2D 里给 `-Camera.main.transform.position.z`）。

## 打包与运行

35. **打包后黑屏/白屏**：最常见原因是 `Scenes In Build` 里没加场景。
36. **打包后写文件失败**：别再往 exe 目录写，用 `Application.persistentDataPath`。
37. **改了 Company/Product Name 会导致 `persistentDataPath` 变化**，老玩家的存档"消失"——发布后别改。
38. **`Application.Quit()` 在编辑器里无效**，只在打包后有效。想在编辑器里退出调试用：
    ```csharp
    #if UNITY_EDITOR
        UnityEditor.EditorApplication.isPlaying = false;
    #else
        Application.Quit();
    #endif
    ```
39. **`OnApplicationQuit` 里不要再弹交互 UI**（窗口已经在关闭），存档要提前做。
40. **打包产出一个文件夹，不能只发 exe**。

## 从控制台迁移最容易犯的思维错

| 控制台习惯 | Unity 里该怎么想 |
| --- | --- |
| "我要写个循环直到游戏结束" | 不需要循环，引擎每帧调 `Update` |
| "开线程让它在后台等输入" | 主线程 `Update` 里查输入，永远不要开线程 |
| "把数据显示到屏幕上" | 数据在 Model，屏幕上的对象是 View，用 `Refresh` 同步 |
| "整个游戏一个有状态的类" | 拆成 Model（纯数据）+ View（表现）+ Controller（调度） |
| "退出前问一下要不要保存" | 每次变化自动保存（退出时无法交互） |
| "发一个 exe 就行" | 发一个文件夹 |

## 想继续深入时可以学什么

按"对做游戏的实际帮助"排序：

1. **协程与 `async/await`（UniTask）** —— 把所有"等一会儿"的写法吃透
2. **ScriptableObject** —— 用来存配置数据（比如"不同数字对应的颜色/图片/音效"），比在脚本里写死数组优雅得多
3. **事件/委托** —— `Action`、`event`，让 Model 变化时自动通知 View（替代"Controller 到处调 Refresh"）
4. **Input System Package** —— 支持手柄、输入重绑定
5. **对象池（Object Pool）** —— 频繁生成销毁对象的优化，2048 用不太上，但做弹幕/粒子会用到
6. **Unity 单元测试（Test Framework）** —— 你的 `BoardModel` 不依赖 Unity，正好可以拿来练手写测试
7. **联机** —— 你有 TCP 服务端经验，可以做"双人对战 2048"，难点在状态同步和延迟处理

祝你玩得开心。
